A recipe file is a TOML file that tells debaser how to check, build, and install a project.
This page lists its keys, their merge rule across layers, and the built-in recipes.
xref:recipe-author/recipes.adoc[Recipes and their layers] explains the layers, trust, and `debaser recipe`.
xref:recipe-author/steps.adoc[Steps, install, and artifact] explains steps, placeholders, the install step, the build output and the installed artifact, `after_build`, and `leftovers`.

== Layers

From the lowest to the highest layer:

[cols="1,2,2,2",options="header"]
|===
|Layer |File |Name in `debaser recipe` |File name in messages

|generic recipe
|Built into debaser
|`generic:<name>`
|`<name>`

|built-in project recipe
|Built into debaser
|`project:<owner>/<repo>`
|`<owner>/<repo> recipe`

|the project's recipe
|`.debaser/recipe.toml` at the fetched upstream commit, used once trusted
|`repo:.debaser/recipe.toml@<commit>`
|`.debaser/recipe.toml at <commit>`

|local recipe
|`recipe.toml` in the xref:overview/concepts.adoc[data directory]
|`local`
|The file's path
|===

`<commit>` is the first seven characters of the upstream commit.
xref:recipe-author/recipes.adoc#the-four-layers[The four layers] says when each layer is present.

== Reading and checking

debaser reads the recipe files when it resolves the effective recipe.
Every error below stops the command with exit 1 and shows the message in the table.

[cols="1,3",options="header"]
|===
|Case |Message

|Not valid TOML
|`<file>: <parser message>`

|A key debaser does not know
|`<file>: unknown key <key>`.
For a nested key, `<key>` carries its place, such as `install.<key>`, `artifact.<key>`, `prompts.<key>`, or `steps[<index>].<key>`.

|A key with the wrong type
|`<file>: <message>`, with the message from the tables below.

|A merged recipe without steps
|`the recipe has no steps`

|A merged `[install]` table without `step`
|`the recipe's [install] table names no step`

|`install.step` names no step of the merged recipe
|`the install step <name> is not one of the recipe's steps`

|`before` or `after` names a step not merged yet
|`step <name> is placed before <other>, which no lower layer has` (or `after`)

|`extends` above the lowest non-generic layer
|`<layer>: extends is only allowed in the lowest non-generic layer (<lowest layer>)`

|A prompt path that does not exist
|`<layer>: prompt file <path> does not exist`
|===

The messages for choosing the generic recipe are in xref:recipe-author/recipes.adoc#generic[How debaser chooses the generic recipe].

== Top-level keys

[cols="2,2,2,3,4",options="header"]
|===
|Key |Type |Default |Merge across layers |Meaning and message

|`name`
|string
|none
|Not merged.
debaser reads it only in the built-in recipes.
|Identifies a built-in recipe: a generic recipe's name, or `owner/repo` for a project recipe.
`name must be a string`

|`recipe`
|string
|none
|Read only from the local recipe.
`recipe` in `patches.json` wins over it.
|Names the generic recipe.
`recipe must be a string`

|`extends`
|string
|none
|Allowed only in the lowest non-generic layer.
`recipe` in `patches.json` or in the local recipe wins over it.
|Names the generic recipe the layer builds on.
`extends must be a string`

|`detect`
|array of strings
|none
|Read only from the generic recipes.
|Files at the fetched upstream commit (or in the working tree debaser runs in when nothing is fetched) whose presence selects the generic recipe.
One match is enough.
`detect must be an array of strings`

|`project_name`
|string
|The repository part of `upstream.repo` in `patches.json`
|A higher layer replaces it.
|The project's name in the prompts for the agent.
`project_name must be a string`

|`+[[steps]]+`
|array of tables
|none
|By step name, see <<step-keys>>.
|The steps that test and build the project, in order.
`+steps must be an array of tables ([[steps]])+`, `steps[<index>] must be a table`, `step <name> appears twice`

|`steps_replace`
|boolean
|not set
|Applies to its own layer: `true` drops the steps of all lower layers before the layer's steps are added.
|`steps_replace must be true or false`

|`[install]`
|table
|none
|Per key, see <<install-keys>>.
|The install step and when it runs.
`install must be a table`

|`[artifact]`
|table
|none
|Per key, see <<artifact-keys>>.
|The build output and the installed artifact.
`artifact must be a table`

|`after_build`
|non-empty array of strings
|none
|A higher layer replaces it.
|A command run in the build directory after the build has fully succeeded.
A failure only warns.
`after_build must be a non-empty array of strings`

|`[prompts]`
|table
|none
|Per entry, see <<prompt-keys>>.
|Overrides for the agent's prompt templates.
`prompts must be a table`

|`leftovers`
|array of strings
|none
|The lists of all layers combine, without duplicates.
|Globs of temporary files the build leaves, matched against paths relative to the build directory.
debaser never commits a matching file with a fix.
`leftovers must be an array of strings`
|===

[#step-keys]
== Step keys

Each `+[[steps]]+` table is one step.
Messages start with the step's place, `steps[<index>]`.

A step whose `name` a lower layer has replaces that step as a whole, at its place in the order; its `before` and `after` are ignored.
A step with a new name goes before the step `before` names, after the step `after` names, or at the end.
When a step sets both, `before` wins.
See xref:recipe-author/steps.adoc#place-a-step-among-the-inherited-ones[Place a step among the inherited ones].

[cols="1,2,2,5",options="header"]
|===
|Key |Type |Default |Meaning and message

|`name`
|string, required
|none
|Names the step; layers merge steps by it.
`steps[<index>].name must be a string`

|`run`
|non-empty array of strings, required
|none
|The command and its arguments, with the placeholders `+{output}+`, `+{root}+`, and `+{tests}+` (see xref:recipe-author/steps.adoc#placeholders-in-commands[Placeholders in commands]).
`steps[<index>].run must be a non-empty array of strings`

|`parser`
|`bun-test`, `tsc`, `cargo-test`, or `generic`
|`generic` (the generic log scan)
|The failure parser for the step's log.
`steps[<index>].parser names no failure parser (known: bun-test, tsc, cargo-test, generic)`

|`timeout`
|positive number of seconds
|none (no timeout)
|Seconds before debaser kills the step.
`steps[<index>].timeout must be a positive number of seconds`

|`before`
|string
|none
|The step a new step goes before.
`steps[<index>].before must be a string`

|`after`
|string
|none
|The step a new step goes after.
`steps[<index>].after must be a string`

|`tests`
|non-empty array of strings
|none (all tests)
|What `+{tests}+` stands for when the step runs in full.
`steps[<index>].tests must be a non-empty array of strings`
|===

[#install-keys]
== `[install]` keys

Each key replaces the lower layer's value on its own; keys a layer leaves out stay as they were.
xref:recipe-author/steps.adoc#the-install-step[The install step] gives the rules for running or skipping it.

[cols="1,1,1,4",options="header"]
|===
|Key |Type |Default |Meaning and message

|`install.step`
|string
|none; required once any layer has `[install]`
|The name of the install step, one of the recipe's steps.
`install.step must be a string`

|`install.triggers`
|array of strings
|empty
|Files whose change since the run's start makes the install step run.
`install.triggers must be an array of strings`

|`install.marker`
|string
|none
|A path in the build directory whose absence makes the install step run.
`install.marker must be a string`
|===

A recipe without an `[install]` table runs every step on every build.

[#artifact-keys]
== `[artifact]` keys

Each key replaces the lower layer's value on its own.
Both paths are relative to the build directory; an absolute path stays as it is.
xref:recipe-author/steps.adoc#build-output-and-installed-artifact[Build output and installed artifact] explains the install and the `.prev` file.

[cols="1,1,2,3",options="header"]
|===
|Key |Type |Default |Meaning and message

|`artifact.output`
|string
|`+{output}+` stands for `debaser-output` in the tree the step runs in.
|The path the build writes, given to steps as `+{output}+`.
`artifact.output must be a string`

|`artifact.install`
|string
|none (nothing is installed)
|Where debaser copies the build output after a successful build, keeping the previous installed artifact as `<path>.prev`.
debaser installs only when `artifact.output` is set too.
`artifact.install must be a string`
|===

[#prompt-keys]
== `[prompts]` keys

Each entry replaces the shipped template of the same name; a higher layer's entry replaces a lower one's.
A value on one line that ends in `.md` is a file path: in the local recipe relative to the data directory, in the project's recipe read from `.debaser/` at the fetched upstream commit.
Any other value is the template text.
Every entry must be a string: `prompts.<name> must be a string`.
xref:recipe-author/harness-verification.adoc#prompts[What each prompt says] lists the placeholders of each template.

[cols="1,4",options="header"]
|===
|Key |Template for

|`prompts.conflict`
|The agent call for a merge conflict, and `fix-conflict.md` at a stop.

|`prompts.check`
|The agent fix of a failing step, and `fix-<step>.md` at a stop.

|`prompts.acceptance`
|The agent fix of a failing acceptance check.

|`prompts.rebase_conflict`
|The agent call for a conflict while rebasing an own branch.

|`prompts.rebase_check`
|The agent fix of a failing step on a rebased own branch.

|`prompts.handoff`
|The per-patch handoff files in the report.
|===
